## 它到底解决什么问题 {data-n="SECTION 00"}

在 61850 之前，一个变电站里可能同时跑着 IEC 60870-5-103、Modbus、DNP3 和五家厂商的私有规约。每接入一台新保护装置，工程师要手工做一张点表：把“地址 40021 的 bit3”对应到“1号主变高压侧断路器合位”。点表在 Excel 里传来传去，改一次现场就可能误动。 {.lead}

### 四个根本性的设计决策

<div class="grid g2">
<div class="card"><div class="h">01 面向对象的自描述</div><p>装置里的数据不再是裸地址，而是带名字、带类型、带品质、带时标的对象。客户端可以在线“浏览”一台从未见过的 IED，自动得到它的完整模型，不需要点表。</p></div>
<div class="card"><div class="h">02 抽象与映射分离</div><p>ACSI（第 7-2 部分）只定义“做什么”——读、写、报告、控制；SCSM（第 8/9 部分）才定义“怎么传”——MMS、GOOSE、SV。将来以太网被替换掉，模型层一行不用改。</p></div>
<div class="card"><div class="h">03 功能分解到逻辑节点</div><p>把“距离保护”“断路器”“互感器”这类功能切成标准化的最小积木 LN，一台物理装置由若干 LN 组合而成。功能怎么分布在装置里，是工程选择，不是标准强制。</p></div>
<div class="card"><div class="h">04 全站可机读的配置</div><p>SCL（第 6 部分）用 XML 描述一次接线、通信网络、每台 IED 的模型和它们之间的订阅关系。工程数据第一次有了可交换、可校验的统一载体。</p></div>
</div>

> [!NOTE] 关键区分
> **互操作（Interoperability）**是 61850 的目标：不同厂家的设备能在同一系统里正确交换信息并协同工作。**互换（Interchangeability）**——把 A 厂的装置拔了换成 B 厂的、配置不动——**不是**标准的目标，实际工程中也做不到。很多对 61850 的失望来自把这两件事搞混了。

### 与传统规约的对照

| 维度 | IEC 60870-5-104 / Modbus | IEC 61850 |
|---|---|---|
| 数据标识 | 信息体地址 / 寄存器号，语义靠人工点表 | 层次化对象名，语义写在标准里 |
| 模型发现 | 不支持，必须事先约定 | 在线自描述，可遍历全部对象 |
| 装置间直传 | 靠硬接线（电缆、开入开出） | GOOSE 组播，毫秒级，带链路监视 |
| 采样传输 | 模拟量电缆到保护屏 | SV 数字采样，光纤过程层 |
| 工程交付物 | Excel 点表 + 各厂私有工程文件 | SCD 全站配置文件（XML） |
| 品质与时标 | 可选、不统一 | 每个数据强制携带 q 与 t |

### 61850-5 定义的十个逻辑接口

标准用 IF1–IF10 标记信息流，写规范和做网络设计时按接口谈需求，比按“哪根网线”谈更准确。

| 接口 | 信息流 | 典型实现 |
|---|---|---|
| IF1 | 间隔层与站控层之间的保护数据交换 | MMS 报告 |
| IF2 | 间隔层与远方保护之间的保护数据交换 | 光纤纵差通道 / 90-1 |
| IF3 | 间隔层内部数据交换 | 装置内部 |
| IF4 | 过程层的 CT/VT 瞬时值传输 | **SV** |

| IF9 | 站控层内部数据交换 | MMS |

### 命名规则的硬性约束

- **LD 名** = IED 名 + LDevice 的 inst。在 MMS 层这是 Domain 名，长度上限 64 字符（Ed1 为 32），实际工程建议控制在 30 以内。
- **LN 名** = 可选前缀（≤6 字符，用于区分同类功能的用途，如 `Q0`、`PROT`）+ 4 字符标准类名 + 实例号（≥1 的整数）。
- **LLN0** 是特殊 LN：每个 LD 必须且只能有一个，无前缀无实例号。数据集、GOOSE 控制块、报告控制块、定值组控制块通常都挂在 LLN0 下。
- **LPHD1** 描述物理装置本身：铭牌 `PhyNam`、健康 `PhyHealth`、上电指示 `Proxy`。
- DO 名允许厂家扩展，但必须在 SCL 的 DataTypeTemplates 里完整声明；扩展名建议加厂家前缀避免与未来标准冲突。

### 一个真实的间隔模型

```
// 220kV 线路间隔测控装置的典型分解
AA1E1Q01CTRL           // LD：控制
 ├─ LLN0                 // 数据集 / 控制块 / 定值组的容器
 ├─ LPHD1                // 物理装置信息
 ├─ Q0CSWI1              // 断路器开关控制
 │   ├─ Pos  [DPC]  分合位置 + 控制
 │   ├─ Loc  [SPS]  就地/远方
 │   └─ Beh  [ENS]  行为状态
 ├─ Q0CILO1              // 联锁：EnaOpn / EnaCls
 ├─ Q0XCBR1              // 断路器本体（过程层映射）
 ├─ Q1CSWI1 / Q1XSWI1   // 隔离开关
 └─ MMXU1               // 三相测量：A/PhV/W/Var/Hz

AA1E1Q01PROT           // LD：保护
 ├─ LLN0
 ├─ PDIS1..5            // 距离保护 I~V 段
 ├─ PTOC1              // 过流
 ├─ PTRC1              // 跳闸逻辑汇总 → Tr / Op
 ├─ RREC1              // 重合闸
 ├─ RBRF1              // 断路器失灵
 └─ RFLO1              // 故障测距
```

> [!NOTE] 建模的自由度
> 标准规定了积木，没规定房子。同一个“三段式过流保护”，A 厂可能建成 `PTOC1/2/3`，B 厂建成一个 `PTOC1` 带三组定值。两者都合规——这正是互换性做不到的根本原因。国家电网/南网的《智能变电站建模规范》就是在标准之上再收紧一层。

### 三个必须吃透的 LN

#### XCBR — 断路器

<div class="kv">
<dt>Pos</dt><dd>DPC，双点位置。<code>stVal</code>：0=中间态 1=分 2=合 3=坏值。合分靠 <code>ctlVal</code>（true=合）。</dd>
<dt>BlkOpn / BlkCls</dt><dd>SPC，闭锁分闸/合闸。</dd>
<dt>OpCnt</dt><dd>INS，操作次数累计。</dd>
<dt>CBOpCap</dt><dd>ENS，断路器操作能力（是否有足够储能）。</dd>
<dt>SumSwARs</dt><dd>BCR，累计开断电流平方和（触头磨损评估）。</dd>
</div>

#### PTRC — 跳闸逻辑

<div class="kv">
<dt>Tr</dt><dd>ACT，跳闸出口。<code>general</code> 为总跳，<code>phsA/B/C</code> 为分相，<code>neut</code> 零序。GOOSE 跳闸报文里传的通常就是它。</dd>
<dt>Op</dt><dd>ACT，保护动作（与 Tr 区分：Op 是本 LN 判据动作，Tr 是最终出口）。</dd>
<dt>Str</dt><dd>ACD，启动，带方向信息 <code>dirGeneral</code>：unknown/forward/backward/both。</dd>
</div>

#### MMXU — 三相测量

<div class="kv">
<dt>A / PhV / PPV</dt><dd>WYE 或 DEL 类型：相电流、相对地电压、线电压，各含 phsA/phsB/phsC/neut/net/res 分量，每分量是 CMV（含幅值 mag 与相角 ang）。</dd>
<dt>W / VAr / VA</dt><dd>WYE，有功/无功/视在功率。</dd>
<dt>TotW / TotVAr / TotPF</dt><dd>MV，三相总量与功率因数。</dd>
<dt>Hz</dt><dd>MV，频率。</dd>
</div>

> [!NOTE] MV 的读法
> 一个 MV（测量值）里有 `instMag`（瞬时值）、`mag`（经死区处理后的值）、`range`（越限区间）、`q`、`t`、`units`、`db`（死区，单位是量程的 0.001%）、`sVC`（换算系数）。**报告和读取用 `mag`，不用 `instMag`**——死区就是为了抑制模拟量刷屏而存在的。

## 功能约束 FC {data-n="SECTION 05"}

同一个 DO 下的属性用途不同：有的是实时状态，有的是配置参数，有的是控制入口。FC 就是给数据属性打的用途标签，它在 MMS 命名里会作为路径的一段实际出现。 {.lead}

| ST | Status information | 状态值，只读。`stVal, q, t, general, phsA` |
| MX | Measurands | 模拟测量值，只读。`mag, cVal, instMag, range` |
| CO | Control | 控制入口。`Oper, SBO, SBOw, Cancel` |
| SP | Setpoint | 可读写的设定值（非定值组）。`setVal` |
| SG | Setting group | 当前生效定值组的值，只读。 |
| SE | Setting group editable | 正在编辑的定值组，可写，需确认后生效。 |
| SV | Substitution | 替代值。`subEna, subVal, subQ, subID` |
| CF | Configuration | 配置参数。`ctlModel, units, db, sVC, minVal, maxVal` |
| DC | Description | 描述。`d, dU, cdcNs, dataNs` |
| EX | Extended definition | 扩展命名空间定义。 |
| BL | Blocking | 闭锁相关属性。 |
| SR | Service response | 服务跟踪响应（Ed2 的 LTRK）。 |
| OR | Operate received | 操作接收信息（Ed2）。 |
| BR / RP | Buffered / Unbuffered report | 缓存与非缓存报告控制块。 |
| LG | Logging | 日志控制块。 |
| GO / GS | GOOSE / GSSE control | GOOSE 控制块。 |

## 公共数据类 CDC {data-n="SECTION 06"}

CDC 规定“一个数据对象由哪些属性构成”。7-4 说 `XCBR.Pos` 的 CDC 是 DPC，7-3 就说清了 DPC 里到底有什么。这是 61850 语义一致性的最后一公里。 {.lead}

| CDC | 类别 | 用途 / 核心属性 |
|---|---|---|
| SPS | 状态 | 单点状态：`stVal(bool) q t` |
| DPS | 状态 | 双点状态：`stVal ∈ {intermediate, off, on, bad-state}` |
| INS | 状态 | 整数状态：`stVal(INT32)`，如 OpCnt |
| ENS | 状态 | 枚举状态：如 Beh、Health、Mod 的当前值 |
| ACT | 状态 | 保护动作：`general phsA phsB phsC neut q t` |
| ACD | 状态 | 带方向的启动：在 ACT 基础上加 `dirGeneral dirPhsA…` |
| SEC | 状态 | 安全违例计数：`cnt sev addr addAddr` |
| BCR | 状态 | 二进制计数器读数（电能脉冲）：`actVal frVal frTm units` |
| HST | 状态 | 直方图（Ed2） |
| MV | 测量 | 单值测量：`instMag mag range q t units db` |
| CMV | 测量 | 复数测量：`cVal.mag cVal.ang`（幅值+相角） |
| SAV | 测量 | 采样值：`instMag q`，专用于 SV 报文 |
| WYE | 测量 | 星形三相组：`phsA phsB phsC neut net res`（每个是 CMV） |
| DEL | 测量 | 三角形组：`phsAB phsBC phsCA` |

| HMV / HWYE / HDEL | 测量 | 谐波量版本 |
| SPC | 可控 | 单点可控：`ctlVal stVal q t ctlModel` |
| DPC | 可控 | 双点可控（断路器/隔离开关的标配） |
| INC | 可控 | 整数可控，如 Mod、分接头挡位设定 |
| ENC | 可控 | 枚举可控，如 Mod（Ed2 用 ENC） |

| LPL | 描述 | 逻辑节点铭牌：`vendor swRev d configRev ldNs` |

### 时标 Timestamp

8 字节：前 4 字节是自 1970-01-01 UTC 起的秒数（SecondSinceEpoch），后 3 字节是秒的小数部分（分辨率约 60ns），最后 1 字节是 **TimeQuality**：

<div class="kv">
<dt>LeapSecondsKnown</dt><dd>是否已知闰秒。</dd>
<dt>ClockFailure</dt><dd>时钟故障，时标不可信。</dd>
<dt>ClockNotSynchronized</dt><dd>未与外部时源同步——<b>失步后必须置 1</b>，否则会误导事故分析。</dd>
<dt>TimeAccuracy</dt><dd>5 位，表示秒小数部分中有效位的位数，0–24，31 表示未指定。</dd>
</div>

时标语义也很关键：变位事件的 `t` 应当是**状态实际发生的时刻**（尽量接近采样/开入去抖后的时刻），不是发报文的时刻，也不是应用处理完的时刻。这一点在做 SOE 精度测试时反复被验证。

> 它是 61850 里唯一“批量”的概念，也是性能关键。一个数据集是若干 FCDA（功能约束数据属性）的有序列表，例如 `<FCDA ldInst="CTRL" lnClass="CSWI" lnInst="1" doName="Pos" daName="stVal" fc="ST"/>`。GOOSE 的收发双方必须对数据集的**成员顺序和类型完全一致**，因为 GOOSE 报文里只有值、没有名字——顺序错位就是最难查的故障。

## 报告与日志 {data-n="SECTION 09"}

报告是站控层获取变位与测量的主通道。它是“订阅—上送”模型：客户端使能控制块，服务端在触发条件满足时主动推送。 {.lead}

</div>

| TrgOps | 触发条件：**dchg** 数据变化 / **qchg** 品质变化 / **dupd** 数据更新 / **integrity** 周期完整性 / **GI** 总召唤 |
| IntgPd | 完整性周期(ms)，配合 integrity 使用，周期性上送全数据集 |
| GI | 写 TRUE 触发一次总召 |
| SqNum / EntryID / TimeOfEntry | 报文序号 / 缓存条目唯一标识 / 入库时间（BRCB 专有） |
| Owner | 当前占用该控制块的客户端标识 |
| ResvTms（Ed2） | BRCB 预留时间，断链后保留缓冲的时长 |

> [!NOTE] 工程要点
> **dchg 与 dupd 的区别**：dchg 是值真的变了；dupd 是值被重新计算/刷新（即使没变）。遥测通常配 dchg + 死区 db，再加一个较长的 IntgPd 兜底；遥信配 dchg + qchg。<br>**控制块是排他资源**：一个 URCB 实例同一时刻只能被一个客户端使能。双机监控系统要保证每台主机用不同实例，否则会出现"抢报告"。

### 日志 Log

日志把事件写进装置内部的循环存储区，由 LCB（日志控制块）控制记录条件（同样有 TrgOps）。客户端事后用 `QueryLogByTime` 或 `QueryLogAfter(entryID)` 检索。它与 BRCB 的区别：BRCB 是推、面向订阅者；Log 是拉、面向历史查询，且不因客户端连接与否而改变记录行为。

## GOOSE {data-n="SECTION 10"}

Generic Object Oriented Substation Event。它替代的是保护屏之间的硬接线电缆：跳闸、闭锁、联锁、失灵启动。设计目标是在 4ms 内送达，且在网络丢包时仍然可靠。 {.lead}

### 为什么它不用 TCP

GOOSE 直接封装在以太网帧上（EtherType `0x88B8`），**没有 IP、没有 TCP**。可靠性不靠重传确认，而靠**周期性重复发送**：只要网络还通，接收方总会在很短时间内再次收到当前状态。这是一种"状态重复"而非"事件传递"的语义——即使某一帧丢了，下一帧携带的仍是完整的当前值。

### 订阅方必须做的检查

1. **链路监视**：TAL 超时 → 置 GOOSE 中断告警（对应 LGOS 的 `St`=false、`StNum`、`LastStNum`）。这是 61850 的一大优势：断线可被发现，硬接线断了没人知道。
2. **stNum 跳变检测**：stNum 突然大幅跳变或倒退，说明发送方重启或有伪造帧。
3. **confRev / numDatSetEntries / 类型**比对：与本地 CID 中订阅配置不一致 → 拒绝并告警。
4. **检修一致性**处理（见 §07）。
5. **ndsCom=TRUE 时不采用**数据。

> [!WARNING] 带宽与风暴
> GOOSE 是组播，交换机默认会向所有端口泛洪。必须靠 **VLAN 划分 + 静态组播过滤（或 GMRP）**把每条 GOOSE 只送到订阅者端口，否则一台装置的 GOOSE 抖动会冲击全网。61850-90-4 专门讲这套网络工程方法。

### R-GOOSE（61850-90-5）

把 GOOSE 封装进 UDP/IP 组播，从而可以跨路由器、跨广域网传输，用于站间保护与广域测量。带有基于 GDOI 的密钥分发和 HMAC 签名。代价是延迟与抖动不再受二层保证，需要谨慎评估。

### 9-2LE 实施导则

原始 9-2 留了太多自由度，UCA 用户组发布了 **9-2LE（Light Edition）**收敛为两档配置，工程上说的“9-2 点对点/组网”基本都指它：

| 用途 | 每周波采样点 | 50Hz 采样率 | 60Hz | 每帧 ASDU 数 |
|---|---|---|---|---|
| 保护 | 80 | 4000 Hz | 4800 Hz | 1 |
| 计量 / 录波 | 256 | 12800 Hz | 15360 Hz | 8 |

### ASDU 内容

```
savPdu
 ├─ noASDU        // 本帧包含的 ASDU 个数
 └─ seqASDU[]
     ├─ svID       // 采样值标识（订阅匹配用）
     ├─ datSet     // 可选
     ├─ smpCnt     // 采样计数器，每秒回绕（如 0..3999）
     ├─ confRev    // 配置版本
     ├─ refrTm     // 刷新时刻，可选
     ├─ smpSynch   // 0 未同步 / 1 本地时钟 / 2 全局时钟（Ed2）
     ├─ smpRate    // 可选
     └─ seqData    // 8 组：i1 i2 i3 i4(中性) v1 v2 v3 v4(中性)
          每组 = INT32 值 + Quality(4字节)

// 9-2LE 定标：电流 1 LSB = 1 mA ；电压 1 LSB = 10 mV
// 即 INT32=1000 表示 1A；INT32=10000 表示 100V
```

> [!WARNING] SV 的三个致命点
> **① 同步**：多个 MU 的采样必须同源同步，否则差动保护会算出虚假差流。`smpSynch` 失效时保护应闭锁差动。<br>
> **② 带宽**：一路保护级 SV 约 4000 帧/秒、每帧百余字节，接近 5–6 Mbps；一个间隔多路叠加，加上 GOOSE，百兆口很快就紧张。<br>
> **③ 抖动**：SV 对延迟抖动极敏感，过程层网络必须做优先级与流量隔离，尽量避免与其他业务混跑。

**点对点 vs 组网**：点对点（MU 直连保护装置光口）延迟确定、无风暴风险，是保护的首选；组网方式便于共享给录波、计量、母差，但需要严格的网络设计。国内智能变电站普遍采用"保护点对点 + 其他组网"的折中。

## 控制模型与 SBO {data-n="SECTION 12"}

遥控是最不能出错的服务。61850 用 `ctlModel` 定义了四种严格程度递增的控制流程。 {.lead}

| ctlModel | 模式 | 流程 | 适用 |
|---|---|---|---|
| 0 | status-only | 不可控，只能读状态 | 纯监视量 |
| 1 | direct-with-normal-security | Operate → 立即响应（+ 状态变化） | 软压板、内部标志 |
| 2 | sbo-with-normal-security | Select → Operate | 较少使用 |
| 3 | direct-with-enhanced-security | Operate → 响应 → **CommandTermination**（含执行结果） | 软压板、部分调度直控 |
| 4 | sbo-with-enhanced-security | SelectWithValue → Operate → CommandTermination | **断路器、隔离开关的标准做法** |

### 常见 AddCause（失败原因）

| AddCause | 含义 | 现场排查方向 |
|---|---|---|
| Blocked-by-switching-hierarchy | 被控制层次闭锁 | 装置在"就地"位置，或站控层未取得控制权 |
| Blocked-by-interlocking | 被联锁闭锁 | CILO 的 EnaOpn/EnaCls 为假，检查五防条件 |
| Blocked-by-synchrocheck | 同期条件不满足 | RSYN 判据、压差/角差/频差定值 |
| Select-failed / Object-already-selected | 选择失败/已被他人选中 | 另一客户端未释放选择，等 sboTimeout |
| Command-already-in-execution | 上一命令未结束 | 等待或检查 operTimeout |
| Invalid-position / Position-reached | 位置无效 / 已在目标位置 | 断路器已在合位又下合闸命令 |
| Parameter-change-in-execution | 正在改定值 | 定值下装未完成 |
| Abortion-by-trip | 被保护跳闸中止 | 操作过程中保护动作 |
| Time-limit-over | 超时 | 选择超时或执行超时 |

> [!NOTE] ctlNum 与 T
> Select 与 Operate 的 `ctlNum`、`origin` 必须一致，服务端据此判断是不是同一次操作。`T` 是客户端发起时刻，服务端可用它做防重放（命令太旧则拒绝）。做遥控问题定位时，先把这两个字段抓出来对。

### 定值组 SGCB

### 替代 Substitution

当某个信号源故障（如位置接点坏了），运行人员可以人工置一个值让上层逻辑继续工作。写 `subVal` + `subQ` 并把 `subEna` 置 TRUE，此后 `stVal` 返回替代值，且 `q.source` 变为 **substituted**——接收方永远能分辨这不是实测量。这比在监控后台"人工置数"要干净得多，因为标记跟着数据走。

### 文件传输

用于取录波文件（COMTRADE 的 `.cfg/.dat`）、下装配置、取日志。服务：`GetServerDirectory(FILE)` 列目录、`GetFileAttributeValues` 取属性、`GetFile` 读、`SetFile` 写、`DeleteFile` 删。映射到 MMS 的 FileOpen/FileRead/FileClose 系列。RDRE 逻辑节点里的 `RcdMade` 变位就是"有新录波了"的通知。

### 服务跟踪 LTRK（Ed2）

把服务调用本身变成可观测数据：谁在什么时候调了 Select/Operate、结果如何、AddCause 是什么，全部体现在 `LTRK` 下的跟踪 DO（如 `CmdTrk`、`RpCBTrk`、`GoCBTrk`、`SgcbTrk`）里，并可被报告上送。这让"后台没收到遥控回应"这类问题第一次有了标准化的证据链。

### ACSI → MMS 的对应关系

| ACSI 概念 | MMS 对应 |
|---|---|
| Server | VMD（虚拟制造设备） |
| Logical Device | Domain |
| LN / DO / DA | Named Variable（结构化命名变量） |
| DataSet | Named Variable List |
| Associate / Release | Initiate / Conclude |
| GetDataValues / SetDataValues | Read / Write |
| GetServerDirectory 等 | GetNameList |
| GetDataDefinition | GetVariableAccessAttributes |
| Report | InformationReport（非确认服务） |
| Log 查询 | ReadJournal |
| 文件服务 | FileOpen / FileRead / FileClose / FileDirectory |
| Control (Oper) | Write 到 `…$CO$…$Oper` 结构 |

```
// 命名转换规则：ACSI 用 "." ，MMS 用 "$"，并把 FC 插到 LN 之后
ACSI:  AA1E1Q01CTRL/Q0CSWI1.Pos.stVal
MMS :  AA1E1Q01CTRL / Q0CSWI1$ST$Pos$stVal
       └── Domain ──┘ └──── Named Variable ────┘

ACSI:  AA1E1Q01CTRL/LLN0.RP.urcb01
MMS :  AA1E1Q01CTRL / LLN0$RP$urcb01

> [!NOTE] 抓包提示
> MMS 跑在 **TCP 102** 端口。Wireshark 里过滤 `mms` 就能看到解析后的服务名。第一次连接会看到 Initiate 协商 PDU 大小与嵌套深度，然后是大量 GetNameList（客户端在"读模型"），之后才是 Read/Write/InformationReport。如果客户端每次上线都要花几十秒，通常就是在遍历一个过于庞大的模型——考虑让客户端缓存 CID 而不是在线读取。

## SCL 配置语言 {data-n="SECTION 15"}

SCL 是 61850 工程化的关键。没有它，自描述模型只能靠在线读取，系统级的订阅关系无法离线校验，多厂家协同就无从谈起。 {.lead}

### 六种文件类型

| 扩展名 | 全称 | 由谁产生 | 内容 |
|---|---|---|---|
| .ICD | IED Capability Description | IED 厂家 | 装置能力：它能提供哪些 LD/LN/DO、支持哪些服务。**不含**工程实例信息 |
| .SSD | System Specification Description | 设计院 / 业主 | 一次系统单线图 + 所需功能（LNode 占位），不含具体装置 |
| .SCD | Substation Configuration Description | 系统集成商 | **全站唯一的总配置**：一次接线 + 通信网络 + 所有 IED + 数据流关系 |
| .CID | Configured IED Description | 系统集成商 → 装置 | 从 SCD 中抽出的、下装给某一台 IED 的配置 |
| .IID | Instantiated IED Description | IED 配置工具（Ed2） | 装置侧完成私有配置后回给系统工具的实例文件 |
| .SED | System Exchange Description（Ed2） | 跨项目交换 | 两个工程之间交换接口信息，如站间 GOOSE |

### 工程流程

```
设计院 ──SSD──▶ ┌──────────────────────┐
                 │  系统配置工具 SCT      │ ──SCD──▶ ┌───────────┐
厂家 ──ICD/IID──▶ │  分配 IED、编数据集、  │          │ IED 配置   │──CID──▶ 装置
                 │  配 GOOSE 收发关系、   │ ◀──IID── │ 工具 ICT   │
                 │  配报告、配通信参数     │          └───────────┘
                 └──────────────────────┘
                          │
                          └──SCD──▶ 监控后台 / 网关机 / 测试仪 / 录波器
```

**Ed1 是单向的**（ICD → SCD → CID），装置侧的私有配置无法回流。**Ed2 引入 IID**形成闭环，解决了"厂家工具改了参数、SCD 不知道"的老问题。

> [!WARNING] SCD 的三条纪律
> ① **SCD 是唯一真源**。任何在装置本地工具里做的改动，必须回到 SCD。现场"临时改一下装置里的数据集"是虚拟回路错乱的头号原因。<br>
>  ② **改数据集必须递增 confRev**，否则订阅方无法感知，会按旧结构解析新报文。<br>
>  ③ **版本管理**：SCD 要像代码一样纳入版本控制，Header 的 version/revision 与 History 元素要如实填写。

| 方式 | 典型精度 | 适用 |
|---|---|---|

| IEEE 1588 PTP（电力规范 C37.238 / 61850-9-3） | ≤1 µs（网络内） | 数字化变电站的主流方案，需交换机支持透明时钟 |

### 61850-5 的同步等级

| 等级 | 精度 | 用途 |
|---|---|---|
| T0 | ±10 ms | 一般事件记录 |
| T1 | ±1 ms | SOE 分辨率 |
| T2 | ±100 µs | 录波 |
| T3 | ±25 µs | 高精度录波 |
| T4 | ±4 µs | 采样值同步（差动） |
| T5 | ±1 µs | 同步相量、行波测距 |

### 报文类型与传输时间

传输时间 **t = t<sub>a</sub> + t<sub>b</sub> + t<sub>c</sub>**：发送方应用把数据交给通信栈到接收方应用拿到数据的**端到端**时间，包含两端协议栈处理和网络传输，不只是线上时间。

| 类型 | 名称 | 性能等级 | 要求 |
|---|---|---|---|
| 1A | 跳闸（Trip） | P1 / P2·P3 | ≤10 ms / **≤3 ms** |
| 1B | 其他快速报文 | P1 / P2·P3 | ≤100 ms / ≤20 ms |
| 2 | 中速报文（测量上送） | — | ≤100 ms |
| 3 | 低速报文（参数、事件） | — | ≤500 ms |
| 4 | 原始数据（SV） | P1 / P2·P3 | ≤10 ms / **≤3 ms** |
| 5 | 文件传输 | — | ≥1000 ms |
| 6 | 时间同步 | — | 按 T0–T5 等级 |

P1 = 配电类应用　P2 = 输电类应用　P3 = 高要求输电类应用

## Mod / Beh / Health 与测试仿真 {data-n="SECTION 17"}

Ed2 把“这个功能现在到底工不工作”正式建模。任何 LN 都有这三个 DO，它们的联动规则是标准里最容易被忽略、又最常出问题的部分。 {.lead}

<div class="kv">
<dt>Mod</dt><dd>模式（可控，ENC）：由运行人员或工程设置。取值 <code>on / blocked / test / test-blocked / off</code>。</dd>
<dt>Beh</dt><dd>行为（只读，ENS）：<b>实际生效的状态</b>。它由本 LN 的 Mod 与上级（LD 的 LLN0.Mod）共同决定——<b>取更受限的那个</b>。</dd>
<dt>Health</dt><dd>健康（只读，ENS）：<code>Ok / Warning / Alarm</code>。自检结果。</dd>
</div>

| Beh | 输出 | 过程值更新 | 说明 |
|---|---|---|---|
| on | 正常输出 | 是 | 正常运行 |
| blocked | **输出闭锁** | 是 | 内部照常计算、状态照常更新，但不出口 |
| test | 输出带 test 标志 | 是 | 数据 q.test=1，接收方按检修规则处理 |
| test/blocked | 闭锁 + test 标志 | 是 | 调试常用 |
| off | 无输出 | **否** | 功能停用，数据品质置 invalid |

> [!NOTE] Beh 的传递规则
> LD 级 `LLN0.Mod` 设为 test，则该 LD 下所有 LN 的 `Beh` 都不会好于 test，**即使各 LN 自己的 Mod 是 on**。现场"投了装置检修压板，为什么某个 LN 还在正常出口"这类问题，先看 Beh 而不是 Mod。

### 仿真（Simulation）—— Ed2 的重要改进

Ed1 只有 test 标志，做过程层测试时无法既让装置接收测试仪的报文、又忽略真实合并单元的报文。Ed2 的方案：

1. 测试仪发出的 GOOSE/SV 帧头把 `simulation` 位置 1。
2. 被测装置的 `LPHD1.Sim` 置为 TRUE（表示"我进入接收仿真报文模式"）。
3. 此后该装置**只采纳 simulation=1 的报文，忽略同一 APPID 的真实报文**；`LPHD1.Sim` 恢复 FALSE 则反之。

这让在线测试可以在不拔光纤的情况下进行，是数字化变电站运维的关键能力。注意 `simulation`（报文来源是仿真的）与 `q.test`（发送装置处于检修状态）是两个正交的概念。

### 一致性测试（61850-10）

厂家需要提供 **PICS**（协议实现一致性声明）、**MICS**（模型实现一致性声明）、**PIXIT**（附加信息，说明标准留给实现的选择项）和 **TICS**（Ed2 增加，技术问题实现一致性）。第三方实验室按 UCA 的测试用例做认证。做系统集成时，**PIXIT 是最有价值的文档**——它写清了"这台装置的 sboTimeout 默认多少""支持几个并发 BRCB 客户端"这类会直接影响联调的信息。

## 网络安全 IEC 62351 {data-n="SECTION 18"}

61850 本身**不含**安全机制：MMS 明文、GOOSE 无认证、任何接入过程层网络的设备都能发出一帧合法的跳闸 GOOSE。安全由配套的 IEC 62351 系列提供。 {.lead}

| 部分 | 内容 |
|---|---|
| 62351-3 | TCP/IP 通信安全：TLS，用于保护 MMS（端口通常改为 3782 或在 102 上协商） |
| 62351-4 | MMS 及应用层安全：认证、端到端安全（Ed2 引入 A-Profile / T-Profile） |
| 62351-6 | 专门针对 61850 的安全规范：GOOSE/SV 的**数字签名**（在 PDU 尾部附加认证值） |
| 62351-7 | 网络与系统管理数据对象（NSM），用安全相关 LN 建模 |
| 62351-8 | 基于角色的访问控制 RBAC |
| 62351-9 | 密钥管理（证书、GDOI 组密钥） |

> [!WARNING] 现实考量
> 给 GOOSE 加签名会引入计算延迟，与 3ms 的跳闸指标直接冲突，因此 62351-6 在保护报文上的落地一直不充分。工程上仍然主要依赖**纵深防御**：物理隔离、过程层网络与站控层网络分离、交换机端口绑定 MAC、禁用未用端口、专用运维通道、安全审计（GSAL 逻辑节点记录安全违例）。中国的电力监控系统安全防护规定（"安全分区、网络专用、横向隔离、纵向认证"）也是同一思路。

mms.confirmedServiceRequest == 5      # Write（Oper 走 Write）

# VLAN 与优先级核对
vlan.id == 1 && vlan.priority == 4
```

### 典型故障与定位思路

| 现象 | 先看什么 | 常见原因 |
|---|---|---|
| GOOSE 中断告警 | LGOS 的 St / LastStNum；抓包看帧是否还在 | 光纤/端口故障；TAL 配置过短；交换机组播过滤把订阅端口漏了；发送方重启 |
| GOOSE 收到但不动作 | confRev、numDatSetEntries、数据集顺序、检修位 | SCD 与装置内配置不一致；两端检修状态不一致；ndsCom=TRUE |
| 遥控失败 | CommandTermination 的 AddCause | 联锁未满足；就地位置；ctlNum/origin 不匹配；被他人选中 |
| 遥测不刷新 | 报告控制块 RptEna、TrgOps、db 死区、IntgPd | 控制块被别的客户端占用；死区设得过大；只配了 dchg 而值恰好稳定 |
| 断链后丢 SOE | 用的是 URCB 还是 BRCB | 该用 BRCB 的地方用了 URCB；ResvTms 太短；缓冲区溢出（看 BufOvfl） |
| 差动保护误动/拒动 | 各 MU 的 smpSynch、smpCnt 对齐、延时补偿 | 对时丢失；PTP 路径不对称；额定延时参数配错 |
| SOE 时标错乱 | Timestamp 的 TimeQuality 位 | ClockNotSynchronized 未置位却已失步；时区/闰秒处理不当 |
| 客户端上线极慢 | MMS 的 GetNameList 数量 | 模型过大、客户端在线读模型；改为离线导入 CID |

## 学习路线与术语速查 {data-n="SECTION 21"}

### 建议的学习顺序

1. **先建立心智模型**：读 61850-1 与 7-1，把“模型 / 服务 / 映射 / 配置”四层关系画出来。
2. **动手看一个真装置**：用 IEDScout 或 libiec61850 的 `examples/iec61850_client_example1` 连一台 IED（或用 `server_example_basic_io` 自建一个），把模型树完整遍历一遍。此时 7-3 与 7-4 才真正读得进去。
3. **抓一次 GOOSE**：让装置变位，用 Wireshark 观察 stNum/sqNum 的变化规律和重传曲线。理解“状态重复”语义。
4. **读一份真实 SCD**：从 Substation 段找到某个间隔，顺着 LNode 追到 IED，再追到 DataSet 和 ExtRef，把一条虚回路从头走通。这一步做完，61850 基本就通了。
5. **做一次遥控**：抓 SelectWithValue → Operate → CommandTermination 的完整交互，故意制造一次失败看 AddCause。
6. **再回头精读 7-2**：此时每个服务都有具体画面，读起来会快得多。
